Implementation notes - 0.5.2 development

Separate tree from hardware-tested c64-pocket-port / published 0.5.1.
Read-only CPU opcode observation exported through cpu_6510/fpga64_sid_iec.
No disk engine, RAM loader, audio, PLL, transport or timing constraint changes.
Only opcode fetches with ROM mapping active qualify; VIC and DMA excluded.
BASIC direct-input entry A483 + KERNAL wait E5CD must settle before typing.
A486 consumes the line. E175 records LOAD; E1A7 proves the normal successful
LOAD path after status checks. A subsequent A483 + settled input permits RUN.
Errors A437/E1D1, input, reset, eject, unavailable loader, attached cartridge,
setting Off cancel. Timeout prevents indefinite pending commands.
Mounted rising edge is synchronized; track refills do not re-arm autostart.
A new startup mount may wait for the first BASIC prompt; later game mounts
are insert-only. Alternate ROM layouts deliberately fall back to manual loading.

Reference for stock ROM entry points (original-source annotated disassembly):
https://pagetable.com/c64ref/c64disasm/
No defgenx implementation imported. Original contact-state-machine implementation.

Activity shares the renderer's existing four clocks, 12x12 pixels (358..369,
8..19), no additional video-domain delay. Host busy uses two-stage CDC;
drive LEDs already run in clk_core. 200 ms persistence makes short IO visible.
A0000028: bit0 autostart, bit1 indicator. Default 3; existing register IDs stable.

Validation scripts: run_autostart.py, run_autostart_cpu.py, run_activity.py,
run_menu_settings.py, run_keyboard_pipeline.py, run_integration.py --reu --dock.
The CPU-tap test executes original diagnostic ROM code, not a Commodore ROM;
it verifies actual fetch alignment and mount/controller integration. The
state-machine tests cover standard ROM event sequences; hardware validation
with real games is still required. Existing regression suites retained.

Final input refinement: assist_controls_ready waits for a neutral controller
report after Pocket menu close. The actual-6510 test covers holding the
menu-closing button, no premature typing/cancellation, release, then manual
cancellation. The long combined video/audio/REU/Dock regression was started
before this isolated guard refinement; its datapaths are unchanged. The
final guard is CPU-integration tested and the final FPGA build/timing rerun.
